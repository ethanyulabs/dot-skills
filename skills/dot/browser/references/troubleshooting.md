# Troubleshooting

| Code | What it means | What to do |
|---|---|---|
| `BROWSER_UNSUPPORTED` / `BROWSER_REQUIRED` (exit 2) | the system's default browser is one dot cannot drive (Safari, Firefox) / none could be found, and nothing is configured | ask the user once which of `installed` to use; pass `--browser`; `config set browser=…` only when they want a default |
| `BROWSER_NOT_INSTALLED` (exit 4) | the chosen browser's `.app` is not there | install it, or `--browser` another one |
| `BROWSER_NOT_RUNNING` (exit 4) | Arc: the user's Arc is not running (the script never launches it, because that would open a window the user did not ask for); Chrome / Edge: dot's own instance is not up | Arc: ask the user to start it, ideally with the port flag; Chrome / Edge: `dbrowser launch --browser chrome`, or just run `open` (it launches by itself, `LAUNCHED` warning) |
| `CDP_UNREACHABLE` (exit 4) | the browser runs without its DevTools port | Arc: give the user the `launch` command from `selftest` (quit Arc, `open -a Arc --args --remote-debugging-port=9222`), then `selftest` again; AppleScript commands keep working meanwhile. Chrome / Edge: `dbrowser quit --browser chrome` then `launch` |
| `PROFILE_LOCKED` (exit 4) | dot's Chrome / Edge instance is running but not on the expected port (started by hand, or with another `--port`) | `dbrowser quit --browser chrome` (falls back to `pkill` on the profile path), then retry |
| `LAUNCH_FAILED` (exit 4) | dot's instance did not open its port within `--timeout` | look at the browser (a dialog? a "restore pages" prompt?); run `launch.shell` by hand; a longer `--timeout` on a slow machine |
| `CDP_CONNECT_FAILED` with 403 / origin | Chromium rejected the websocket handshake | Arc: relaunch with `--remote-debugging-port=9222 --remote-allow-origins=*` |
| `AUTOMATION_DENIED` (exit 4) | macOS did not allow this process to send Apple events to Arc (message names Arc) or to System Events (message names System Events; Chrome / Edge use it to put the user's app back after a window came to the front) | 系统设置 → 隐私与安全性 → 自动化：给运行 dbrowser 的终端 / 应用勾上 Arc 或 System Events；第一次会弹窗，让用户点「允许」后重试。System Events 被拒时命令仍然能跑，只是开窗后不会把原来的应用放回前台 |
| `NO_WINDOW` | Arc has no main window (only Little Arc, or all windows closed) | ask the user to open a window (⌘N); the script never creates tabs at the application level because those become Little Arc popups |
| `SPACE_REQUIRED` / `SPACE_NOT_FOUND` | Arc: no space named and none configured / no space with that title | ask once from `spaces`; offer `config set arc.space=…` only when the user wants a default; `--space id:<uuid>` for duplicate titles |
| `SPACE_IGNORED` (warning) | `--space` was given for a browser without spaces (Chrome / Edge) | nothing; dot's instance is the isolation |
| `LOCK_TIMEOUT` | another `open` has held `~/.dot/browser/lock` for more than the timeout | wait and retry; delete the lock only when no dbrowser process is running |
| `TARGET_NOT_FOUND` / `AMBIGUOUS_TARGET` (warnings on `open`) | Arc: no DevTools target matched the URL in time / several did; a tab the user opened at the same moment is never taken | `attach --session N --tab-id ARC_ID [--target-id T]`; the Arc tab and the session exist either way |
| `INVALID_URL` | Arc's `make new tab` refused the URL (`data:` and other non-web schemes); the space was switched and switched back inside the script | use an http(s) or file URL |
| `SESSION_EXISTS` | `--session NAME` is already in use (maybe by another agent) | `dbrowser close --session NAME` if it is yours, else another name |
| `BAD_ARGS` naming two browsers | `--browser X` on a session that belongs to browser Y | drop `--browser`; session commands know their browser |
| `TARGET_GONE` | the tab is there but exposes no DevTools target even after a background reload (asleep, archived, or a non-web page) | Arc: ask the user to click the tab once, then `attach --session N --tab-id ARC_ID`; or open the page again |
| `TAB_GONE` | the session's tab no longer exists | `open` again; `close --keep-tab` forgets the session |
| `REF_STALE` | the page navigated or the element disappeared since the snapshot | `snapshot` again; chain actions with `--snapshot` |
| `ELEMENT_NOT_FOUND` / `NOT_VISIBLE` / `ELEMENT_DISABLED` | selector matched nothing / the element had no rendered box / stayed disabled within `--timeout` | snapshot and pick a ref; look for the control that reveals or enables it; a longer `--timeout` for slow pages |
| `SCREENSHOT_NEEDS_FOREGROUND` | Chromium did not render the background tab | use `extract` / `eval`; `--activate` only with the user's agreement; on Arc a second window on the agent's space makes screenshots work without any switching; on Chrome / Edge this should not happen (each session has its own window, the launch flags keep covered windows rendering) |
| `OSA_ERROR` containing `-1700` | an AppleScript object reference could not be resolved (Arc's known quirk when an object is stored in a variable or returned from `make`) | this is a bug in the script text, not the page: report it with the message; the shipped scripts use inline specifiers only |
| `OSA_TIMEOUT` | Arc did not answer AppleScript in time | Arc may be showing a modal dialog; look at it, then retry |
| `WAIT_TIMEOUT` | the condition did not hold within `--timeout` | snapshot or screenshot to see where the page actually is |
| `CONFIG_INVALID` / `CONFIG_BAD_KEY` | `config.json` is not valid JSON / a key such as `space`, `port` or `chrome.space` does not exist | fix or delete the file (never overwritten by the script); keys are `browser`, `arc.space`, `arc.port`, `chrome.port`, `edge.port` |
| `MIGRATION_HINT` (warning) | `~/.dot/arc/config.json` from the former `dot arc` exists and is not read | run the `config set` line in the warning once; the old directory can be deleted |
| `SESSIONS_LEFT` (warning on `quit`) | sessions of that browser still have files | `dbrowser close --keep-tab --session <name>` for each |
| `QUIT_TIMEOUT` (warning on `quit`) | `Browser.close` was sent (and, after a 3 s grace, `pkill`), but the process was still there at `--timeout` | run `quit` again, or look at the window (a "close all tabs?" prompt) |

Other things worth knowing:

- Arc: spaces belong to the profile, not the window: every window lists the same spaces; `active space` is per window and the script always talks to the front window. `tabs of front window` is every tab in every space, which is why tab ids are unique and `attach --tab-id` works across spaces. Arc switches the front window to a tab it just created; `open` undoes that in the same script (`restored: true`). Right after a relaunch no tab is loaded and the front window may have no active tab. Arc lets background tabs sleep after a while; their DevTools target disappears and comes back on reload (`rebound: true`).
- Chrome / Edge: the user's own Chrome can be open at the same time; dot's instance is a separate process with a separate profile (`pgrep -f -- --user-data-dir=<profile>` is how `running` is decided). The frontmost app is tracked by pid through System Events, so the user's own Chrome is never confused with dot's, and an app the user switched to themselves is never pulled back. Two agents starting the instance at once share `~/.dot/browser/lock`; a process that is there without the port gets `--timeout` to open it before `PROFILE_LOCKED`. First use of a site: log in once in the dot window (`open <login page> --browser chrome --focus`). Chrome 136+ refuses `--remote-debugging-port` on the default profile, which is why there is a dedicated one. Edge shares the code path but was not tested on a real Edge.
- The DevTools port is loopback-only but unauthenticated: any local process can use it while the browser runs with the flag. Recommend a normal relaunch of Arc / `dbrowser quit` after the task.
