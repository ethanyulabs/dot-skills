# dot browser: drive the user's browser (Arc, Chrome, Edge)

Subcommand of the `dot` skill; `SKILL_DIR` is the `dot` directory and `BROWSER_DIR` is `$SKILL_DIR/browser`, which holds this file. macOS only. Needs uv (https://docs.astral.sh/uv/): `scripts/dbrowser.py` declares its one dependency inline (`websockets`), a few hundred KB on first run. Page interaction goes through the Chrome DevTools Protocol on every browser. The browser side differs (`references/browsers.md`): **Arc** has spaces, is driven through its AppleScript dictionary and must be started once by the user with `--remote-debugging-port=9222` (macOS asks once for permission to control Arc); **Chrome** and **Edge** refuse that port on their everyday profile (Chrome 136+), so dot launches its own instance with a dedicated profile under `~/.dot/browser/profiles/<browser>/`, one window per session, and the user logs in there once. Version 0.6.0.

Usage: `/dot browser <action> [args]` (Codex: `$dot browser …`), or plain language such as "在 byted 空间打开 …", "用 Arc 登录态抓一下这个页面", "用 Chrome 打开这个页面点一下那个按钮", "open this in Chrome", "in the agent space". The user's browser stays theirs: every command runs in the background and never switches the space, tab or window they are looking at unless they asked to watch (`--focus`) or to be shown (`--activate`); whatever the browser raised on its own is put back inside the same command (`restored: true`; a flicker at most). Several agents can run at once, each in its own session. The user's home `~/.dot/browser/` (`DOT_HOME` moves the `~/.dot` root) holds the defaults (`config.json`: default browser, default space and port per browser), the sessions, the dedicated profiles and every output.

## Actions

| Action | Invocation | What it does | Read |
|---|---|---|---|
| `selftest` | `dbrowser selftest [--browser B] [--deep]` | which browser is in use and why, whether it is installed, running, reachable on its DevTools port (for Arc, allowed to be automated; for Chrome / Edge, allowed to ask System Events which app is in front); prints the launch command when the port is closed; `--deep` also opens one websocket | `references/principles.md` |
| `launch` / `quit` | `dbrowser launch [--browser chrome\|edge]`, `dbrowser quit [--browser chrome\|edge]` | start / stop dot's own Chrome or Edge instance (dedicated profile, background, never the user's own browser); `open` / `attach` / `tabs` launch it by themselves when needed; on Arc `launch` only reports whether the port is up (starting Arc is the user's, `BAD_ARGS` when it is not up) and `quit` is refused | `references/browsers.md` |
| `spaces` / `tabs` | `dbrowser spaces` / `dbrowser tabs [--space S \| --all]` | Arc: the spaces of the front window (active one marked, configured default shown) and the tabs of one space; Chrome / Edge: no spaces (`isolation: instance`), the tabs of dot's instance | `references/spaces.md` |
| `open` | `dbrowser open <url> [--browser B] [--space S] [--session N] [--focus] [--no-wait]` | a new tab (Arc: in the space; Chrome / Edge: in a new window) bound to a DevTools target, saved as a session; silent by default | `references/spaces.md` |
| `attach` | `dbrowser attach (--active \| --tab-id ID \| --url U) [--session N] [--target-id T]` | a session on a tab that is already open (the user's current Arc tab, a logged-in page) | `references/spaces.md` |
| `goto` / `back` / `forward` / `reload` / `close` | `dbrowser goto <url>`, `dbrowser back`, `dbrowser reload`, `dbrowser close [--keep-tab]` | navigate the session's tab (no focus change); close the tab (and its window on Chrome / Edge) and forget the session | `references/spaces.md` |
| `sessions` | `dbrowser sessions` | every session with its browser, space, URL and whether its target is still alive | `references/spaces.md` |
| `snapshot` | `dbrowser snapshot [--root SEL] [--depth N] [--boxes] [--max-chars N]` | the accessibility outline of the page with `[ref=eN]` on everything clickable or focusable | `references/interact.md` |
| `click` / `fill` / `press` / `wait` | `dbrowser click <ref\|selector> [--double] [--button right]`, `dbrowser fill <ref\|selector> <text> [--press Enter]` (text that starts with `-`: `dbrowser fill e7 -- "-text"`), `dbrowser press <key> [--target …]`, `dbrowser wait --url GLOB \| --selector SEL \| --text T \| --ms N \| --load load\|domcontentloaded` | act on the page with Playwright's actionability rules (wait until visible and enabled, up to `--timeout`); selectors `css=` / `xpath=` / `text=` / `role=button[name="Go"]`; every one takes `--snapshot` to return the fresh outline in the same call | `references/interact.md` |
| `screenshot` / `extract` / `eval` | `dbrowser screenshot [--out PATH] [--full] [--target …] [--activate]`, `dbrowser extract [--what text\|links\|html\|title] [--root SEL] [--out FILE]`, `dbrowser eval <js> [--out FILE]` | see the page, read it as text, run JavaScript in it | `references/read.md` |
| `endpoint` | `dbrowser endpoint [--session N]` | where a real Playwright (or any CDP client) can attach: the HTTP endpoint, the browser websocket and, with a session, that tab's target | `references/playwright.md` |
| `config` | `dbrowser config show` / `config set browser=chrome arc.space=NAME chrome.port=N` / `config unset KEY` | the default browser and, per browser, the default space (Arc only) and port, in `~/.dot/browser/config.json`; `--browser` / `--space` / `--port` on any command override the defaults without changing them | `references/principles.md`, Home directory |

Every command takes `--browser`, `--port`, `--session` (or `DOT_BROWSER_SESSION`), `--space`, `--timeout MS` and `--quiet`, prints one JSON line and exits 0 / 2 / 4 / 5 (`references/principles.md`, Output contract). The result's `browser` field says which browser was used and why (`flag`, `session`, `config`, `system`).

## Steps

1. **Orient.** Read `references/principles.md` and follow its Step 0: set `SKILL_DIR` and `BROWSER_DIR`, define `dbrowser` as `uv run --script <BROWSER_DIR>/scripts/dbrowser.py`, run `dbrowser selftest`. `"ok": true` with every check true is the expected result. If it fails with `BROWSER_UNSUPPORTED` / `BROWSER_REQUIRED` (exit 2), go to Step 2 first. If `checks.cdp` is false on **Arc**, the page commands (`snapshot`, `click`, `fill`, `press`, `wait`, `screenshot`, `extract`, `eval`, `endpoint`) are unavailable until Arc is relaunched; the AppleScript commands (`spaces`, `tabs`, `open`, `attach`, `goto`, `back`, `forward`, `reload`, `close`, `sessions`, `config`) keep working, and `open` / `tabs` already return each tab's `title` and `url`. So: if the request needs only those (open a page, read its title or address, navigate, close), finish it with them and say in the report that page commands were unavailable; otherwise give the user `launch.zh` and the `launch.shell` line as they are, do the AppleScript part if it helps, and stop there. On **Chrome / Edge** `BROWSER_NOT_RUNNING` only means dot's instance is not up yet: `open` starts it by itself (`LAUNCHED` warning), or run `dbrowser launch --browser chrome`. If `checks.automation` is false, follow `references/troubleshooting.md`, Automation permission.
2. **Pick the browser.** In this order: the browser the user named ("用 Chrome" → `--browser chrome`); the configured default (`config.browser`); the system's default browser (what `selftest` reports as `browser.source: system`). When the system default is not supported (Safari, Firefox) and nothing is configured, ask the user once which of the installed ones to use (`installed` in the error), pass it with `--browser`, and offer `dbrowser config set browser=…` only when they say "以后都用 …". A page the user is logged into in Arc needs Arc; Chrome / Edge sessions live in dot's own profile, so the first task on a site needs the user to log in there once (`open <login page> --browser chrome --focus`, then wait for them).
3. **Pick the space** (Arc only; Chrome / Edge have no spaces and ignore `--space` with a `SPACE_IGNORED` warning). In this order: the space the user named ("在 X 空间" → `--space X`); the configured default (`selftest` prints it as `default_space`); otherwise run `dbrowser spaces` and ask the user once which one, listing the titles. When the user says "以后都用 X" / "always use X", run `dbrowser config set arc.space=X` and say it is saved; a space named for one request is passed with `--space` and never saved.
4. **Get a session.** `dbrowser open <url> [--browser B] [--space S]` for a new page, or `dbrowser attach --active` when the user says "this page" / "这个页面" and is on it in Arc. Copy `export_hint` into the shell before the next command (`export DOT_BROWSER_SESSION=<name>`); an agent whose shell resets between commands passes `--session <name>` on every command instead. Session commands take the browser and port from the session, so `--browser` is not needed again. A `--session NAME` you choose must be new (`SESSION_EXISTS` otherwise: another agent may be using it). One session per task; never open a second tab to recover from a stuck page.
5. **Work the page in a loop.** `dbrowser snapshot` to see what is there, then `dbrowser click e12` / `dbrowser fill e7 "text" --press Enter` / `dbrowser press Enter`, each with `--snapshot` so the next ref is never stale; `dbrowser wait --url …` after a submit; `dbrowser extract` when the user wants the content. `REF_STALE` means the page changed: take a new snapshot, do not guess. At most two blind retries of the same step; then `dbrowser screenshot`, open the PNG with the Read tool, and decide or ask. Every interaction stays in the session's tab. A long, many-step task on one page may be cheaper with a real Playwright attached through `dbrowser endpoint` (`references/playwright.md`).
6. **Look before you report.** Any time the user asked to see the page, the page looks wrong, or the report makes a visual claim, run `dbrowser screenshot` and open the file with the Read tool. `SCREENSHOT_NEEDS_FOREGROUND` means the tab is in the background and Chromium did not render it: read the page with `extract` / `eval` instead; add `--activate` only when the user agreed that the browser may flash to that tab for a moment (it switches back by itself). When page commands are unavailable (Step 1), this step is skipped and the report says so.
7. **Finish.** `dbrowser close` unless the user wants the tab kept (`--keep-tab` forgets the session only). A coordinating agent that dispatched several sub-agents runs `dbrowser sessions` and closes what they left. On Chrome / Edge, when `dbrowser sessions` shows nothing left for that browser and the user is done, `dbrowser quit --browser chrome` closes dot's instance (and its open port). Report in Chinese with `assets/templates/report.zh-CN.md`.

Sensitive actions (paying, sending a message or mail, deleting, granting a permission, changing account settings) run only when the user named that action in this conversation; otherwise stop before the click and ask. Never type a password or code the user did not give in this conversation; when a page asks the user to sign in, say so and let them do it in the browser (Arc: their window; Chrome / Edge: the dot window, raise it with `--focus` on request), then continue. Several agents at once: each uses its own session and, on Arc, where possible its own space; no `--focus`, no `--activate` without the user's say-so.

## Done when

- The user's goal on the page is reached, or the user knows exactly what blocks it (which step, which error code, what they can do).
- Every screenshot the report mentions was opened with the Read tool, and every statement about what the page shows comes from a snapshot, an extract or a screenshot of this run.
- The space, tab and window the user was looking at are the ones they are looking at now; `--focus` / `--activate` were used only on request.
- The session is closed, or the user asked to keep the tab; nothing was committed.
